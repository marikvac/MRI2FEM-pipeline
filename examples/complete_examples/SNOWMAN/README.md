# snowman-mesh

An example workflow demonstrating how to convert separate `.stl` surface geometries into a single, FEM-ready 3D computational mesh using the **Gmsh** OpenCASCADE (`occ`) kernel.

---

## Overview

This project walks through a two-stage pipeline using two example geometries—a snowman (`snowman_parts.stl`) and a top hat (`tophat.stl`)—to show how surface meshes can be reconstructed as CAD volumes, aligned, fragmented into compatible regions, and meshed in 3D[cite: 1, 2].

1. **STL to STEP & Volume Reconstruction (`snowman_create_step.py`)** – Loads triangular `.stl` meshes, rebuilds points, lines, curve loops, plane surfaces, a surface loop, and a 3D volume in the OCC kernel, exports `.step` files, and writes model diagnostics[cite: 1].
2. **Alignment, Fragmentation & 3D Meshing (`snowman_mesh.py`)** – Imports the `.step` geometries, repositions the top hat onto the snowman, applies `occ.fragment()` to create conformal interfaces/regions for FEM simulations, assigns 3D physical groups, and exports a `.msh` mesh[cite: 2].

---

## Expected Project Structure

* `stl_files/` – Input `.stl` files (`snowman_parts.stl`, `tophat.stl`)[cite: 1]
* `step_files/` – Output `.step` geometry files generated by `snowman_create_step.py` (must exist or be created before writing outputs there)[cite: 1, 2]
* `snowman_create_step.py` – Converts `.stl` files into OCC 3D volumes/STEP files and writes summary `.txt` diagnostics[cite: 1]
* `snowman_mesh.py` – Translates, fragments, assigns physical groups, and generates `snowman_with_hat.msh`[cite: 2]

---

## How to Run the Workflow

### 1. Generate STEP Files and Model Info
Run `snowman_create_step.py` first to convert the input STL files into STEP volumes and inspect geometry/mesh statistics[cite: 1].

* Reads inputs from `stl_files/snowman_parts.stl` and `stl_files/tophat.stl` (configured at the bottom of the script)[cite: 1].
* Reconstructs each STL as a closed OCC volume and writes output to `step_files/<model_name>.step` (`snowman.step` and `tophat.step`)[cite: 1].
* Writes diagnostic reports (`<model_name>.txt`, such as `snowman.txt` and `tophat.txt`) containing entity counts (0D–3D), bounding box coordinates/dimensions/center, and node counts[cite: 1].

### 2. Align, Fragment, and Generate the 3D Mesh
Run `snowman_mesh.py` after the STEP files have been created[cite: 1, 2].

* Imports `step_files/tophat.step` first, translates it along `z` (`dz = 34.5`) so it sits properly on the snowman, and then imports `step_files/snowman.step`[cite: 2].
* Runs `gmsh.model.occ.fragment()` with the snowman as the object and the translated top hat as the tool to produce compatible regions for finite element analysis[cite: 2].
* Defines 3D physical groups (`tophat`, `hothead`, and `snowman` with tags `1`, `2`, and `3`)[cite: 2].
* Generates the 3D mesh and saves it to `snowman_with_hat.msh` in the current working directory (adjustable via the `gmsh.write(...)` call at the end of the script)[cite: 2].
